# Contributing

CallBridge is a telephony application. It handles call detail records, contact data, and
ConnectWise identifiers, and it runs a local HTTP service on the technician's workstation.
Both of those raise the bar for changes.

## Development workflow

1. Create a focused branch from the current default branch.
2. Keep credentials and customer data out of source, tests, logs, screenshots, and commits.
3. Add or update tests for behavior changes.
4. Run the desktop build, service tests, and relevant smoke tests locally.
5. Open a pull request describing behavior, risk, verification, and rollback considerations.

Pull requests must pass CI, security scanning, dependency review, and human review before
merge. Production releases must be generated from a reviewed tag rather than a developer
workstation.

## Requirements

- Windows 10 or Windows 11
- .NET 8 SDK

## Run locally

```powershell
.\Start-CallBridge.ps1
```

The launcher generates an ephemeral local API credential, removes only a verified orphaned
CallBridge service from the selected port, starts the service on loopback, starts the
desktop application, and stops the service it owns when the desktop exits.

Runtime data lives under `%LOCALAPPDATA%\IT Health Technologies\CallBridge`. Default call
history retention is 90 days; override for a session with `-CallRetentionDays`.

## Verify before opening a pull request

```powershell
dotnet restore .\CallBridge.sln
dotnet build .\CallBridge.sln -c Release --no-restore
dotnet test .\tests\CallBridge.Service.Tests\CallBridge.Service.Tests.csproj -c Release --no-build
dotnet run --project .\src\CallBridge.Desktop\tests\CredentialSmokeTest.csproj -c Release
dotnet run --project .\src\CallBridge.Desktop\tests\ConnectWiseSmoke\ConnectWiseSmoke.csproj -c Release
dotnet run --project .\src\CallBridge.Desktop\tests\SipMediaSmoke\SipMediaSmoke.csproj -c Release
```

`TreatWarningsAsErrors` is enabled repository-wide — a warning is a build failure, so do not
leave one for later. Builds are deterministic and restore uses lock files; if you change
dependencies, commit the updated lock file.

## Rules that must not be weakened

These encode CallBridge's security posture. A change that breaks one needs an explicit
decision, not a passing test.

1. **The service binds to loopback only.** Never add a configuration option, debug flag, or
   test hook that binds another interface.
2. **Every route except `/health` requires the per-session bearer credential.** The
   credential is random per session and generated by the launcher. Do not add an
   unauthenticated route, and do not introduce a static or predictable fallback credential.
3. **Reject browser origins and non-loopback host headers.** This is what stops a web page
   on the technician's machine from driving the phone.
4. **No certificate bypass for TLS SIP signaling.** Validation uses the Windows trust chain.
   Do not add a "skip verification" switch, not even behind a debug build.
5. **Desktop secrets stay DPAPI-protected and out of serialized settings.** Never widen what
   gets written to a settings file.
6. **Bounded requests and quiet logs.** Request sizes and rates stay bounded, and logs must
   omit sensitive payloads — numbers, call content, contact records, tokens.
7. **Retention and deletion stay honest.** Call history has configurable retention,
   authenticated export, and confirmed deletion. Silently retaining data past the configured
   period is a defect.

## Test data

Use synthetic `555` telephone numbers and `example.invalid` domains in tests, fixtures,
documentation, and screenshots. Never use a real customer number, ConnectWise identifier, or
recording.

Treat telephone numbers, call history, recordings, contact data, ConnectWise identifiers,
and support notes as sensitive in every context, including issue reports.

## Emergency calling

CallBridge is **not yet approved for production emergency calling**. Do not add UI, copy, or
documentation implying that it is, and do not remove that caveat from the README without an
explicit decision from the repository owner.

## Commits and pull requests

- Imperative subject line, under ~72 characters.
- Explain _why_ in the body; the diff already shows what.
- Note which of the seven rules above your change touches, if any.
- State the rollback path for anything affecting the service, credential handling, or
  persistence.

## Security

Report suspected vulnerabilities privately — see [SECURITY.md](SECURITY.md), never a public
issue. Architecture and trust boundaries are in
[docs/SECURITY-ARCHITECTURE.md](docs/SECURITY-ARCHITECTURE.md).
